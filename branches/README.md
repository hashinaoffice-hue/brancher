# Branches

브랜처의 모든 프로젝트는 하나의 브랜치입니다. 개별 프로젝트의 작업은 각자의 저장소에서 하고, 여기에는 **브랜드 관점의 기록**만 남깁니다.

## 상태

Git의 흐름을 그대로 씁니다.

| 상태 | 의미 |
|---|---|
| `open` | 만드는 중 |
| `shipped` | 출시. 시장에서 검증 중 |
| `merged` | 검증 완료. 본격적으로 키운다 |
| `closed` | 중단. 회고와 숫자를 남긴다 |

- 번호는 재사용하지 않습니다. `closed`된 브랜치도 번호를 유지합니다.

## 목록

| `branch 02` | 준비 중 | | | | |

## 브랜치 기록 템플릿

새 브랜치를 열 때 `branch-NN-이름.md`로 복사해서 씁니다.

```markdown
# branch NN ▸ 이름

- 한 줄: (무엇을, 누구에게)
- 상태: open
- 시작: YYYY.MM.DD
- 출시: —

## 왜 이 브랜치인가
- 문제:
- 사업성 근거:

## 검증 기준 (merge 조건)
출시 후 N주 안에 이 숫자를 넘으면 merge, 못 넘으면 close.
- 지표 1:
- 지표 2:

## 숫자 로그
| 날짜 | 지표 | 값 | 메모 |
|---|---|---|---|

## 회고 (merge / close 시)
```

> 검증 기준을 **출시 전에** 적어두는 것이 핵심입니다. 그래야 "Merge what works"가 감이 아니라 원칙이 됩니다.
