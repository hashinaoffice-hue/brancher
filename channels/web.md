# Web — 포트폴리오 웹앱

> 상태: 시안 v2 (2026.11.25) — https://claude.ai/artifact/FBwWKj9Jxavz52zkwMe2t5 (비공개 링크, v1과 같은 주소)
> 주소 `brancher.kr`. 구현 위치는 Q10. 다음 시안의 연출·기능 설계: [`web-direction.md`](web-direction.md)

## 역할

인스타 바이오 링크의 도착지. 한 앱에 얼굴이 둘이다.

| | 공개 페이지 | 관리자 모드 |
|---|---|---|
| 누가 | 방문자 (고객 > 협업 상대 > 파트너) | 나 한 명 |
| 무엇 | 브랜처 소개 · 만든 것 · 문의 | 인사이트 · 가지 관리 · 문의함 |
| 어떻게 | 주소로 접속 | 같은 주소를 **PWA로 설치** → 로그인 |

- 세 목적(브랜드북 Purpose)과 맞물린다. 만든 것 = 포트폴리오, 서비스 바로가기 = 제품 홍보, 인사이트 = "반응이 오는 것만 키운다"의 판단 근거.
- **이 웹앱은 가지가 아니다.** 번호를 붙이지 않는다. 가지들이 모이는 `main`이다.

## 컨설턴트 의견 — 만들기 전에

**1. 두 개의 제품이다. 나눠서 내놓는다.**
공개 페이지는 며칠 일이다. 관리자 인사이트는 분석 도구 하나를 만드는 일이다. 둘을 묶으면 인스타 링크는 몇 주 동안 비어 있다. Ship fast에 따라 공개 페이지를 먼저 내놓는다.

**2. 분석은 직접 만들지 않는다.** (Q8)
수집·집계·저장은 이미 잘 만든 도구가 있다. 직접 만들 가치가 있는 건 하나뿐이다: **모든 가지를 한 화면에, merge 기준과 나란히.** 이건 어떤 도구에도 없다. 관리자 모드는 이 화면에 집중하고, 깊은 분석은 도구로 넘긴다.

**3. 숫자는 대시보드보다 먼저 쌓여야 한다.**
첫 배포부터 분석 스크립트를 심는다. 대시보드는 나중에 만들어도 지난 숫자를 볼 수 있다. 반대로 하면 출시 첫 주의 숫자를 잃는다.

**4. 문의 폼은 메일을 대체하지 않는다.**
폼 = 저장 + 메일 알림. 메일 주소는 계속 보인다 (2026.10.28 결정: 문의는 메일). 폼을 쓰기 싫은 사람이 있고, 폼이 고장 나는 날이 있다.

**5. 아직 공개된 가지가 없다.**
`branch 01`은 출시 준비 중이다. 비어 있는 "만든 것"은 약하다. 그래서 이름 없이 번호와 상태만 보인다 → `branch 01 · 만드는 중`. 사실이고, 다음을 기다리게 한다.

## 공개 페이지

한 페이지, 위에서 아래로.

| 순서 | 블록 | 내용 |
|---|---|---|
| 1 | 머리 | 워드마크 `brancher.` (로고 파일) · 1인 개발 브랜드 · **빠르게 만들고, 천천히 키운다.** |
| 2 | 만든 것 | 가지 카드 목록. 최신 번호가 위 |
| 3 | 방식 | 뻗는다 · 내놓는다 · 키운다 (게시물 003과 같은 문장) |
| 4 | 문의 | 메일 주소 + 폼 |
| 5 | 바닥 | Branch out. Build ventures. · `@brancher.dev` |

문구는 [`brand/intro.md`](../brand/intro.md) "소개 페이지"를 그대로 쓴다.

### 가지 카드

```
■ branch 01 ▸ 핸드머니
  계획·기록·검토 자산관리 앱
  출시 · 2026.MM.DD
  [바로가기]
```

- 형식은 인스타 프로젝트 카드와 같다. 카드를 누르면 상세: 무엇 / 왜 / 기술 / 기간 / 상태. 기술은 상세에만 (동료 개발자용).
- **사용자 수는 넣지 않는다** (2026.11.25). 사용자가 늘면 다시 검토한다.
- 고객이 읽는 화면이라 상태는 한국어로 바꿔 쓴다.

| 내부 상태 | 화면 표기 | 스퀘어 |
|---|---|---|
| `open` | 만드는 중 | 회색 외곽선 |
| `shipped` | 출시 | 그린 |
| `merged` | 키우는 중 | 그린 |
| `closed` | 종료 | 회색 — 공개 여부는 Q3 |

> 그린 스퀘어 = 결과물. 내놓은(ship) 가지에만 그린을 준다. 만드는 중인 가지는 아직 마침표가 없다.

### 문의 폼

| 항목 | 필수 | 문구 |
|---|---|---|
| 회신 메일 | ✓ | `회신 받을 메일` |
| 내용 | ✓ | `내용` |
| 개인정보 안내 | — | `회신에만 씁니다. 처리 후 1년 뒤 삭제합니다.` |

- 이름·회사·문의 종류는 받지 않는다. 받는 만큼 지켜야 할 것이 늘고, 문의 종류는 나열하지 않기로 했다 (2026.10.28).
- 버튼: `보내기`
- 완료: `받았습니다. 메일로 답장합니다.`
- 실패: `보내지 못했습니다. brancher.lab@gmail.com으로 보내주세요.`
- 스팸 방지는 보이지 않는 방식으로 (허니팟·속도 제한). 퍼즐 캡차는 쓰지 않는다.

## 관리자 모드

나만 본다. 그래서 Git 용어를 그대로 쓴다.

| 화면 | 보이는 것 |
|---|---|
| **main** (첫 화면) | 가지마다 한 줄: DAU · WAU · MAU · 지난주 대비. 맨 위에 포트폴리오 방문자와 새 문의 수 |
| **branch NN** | 사용자 추이, 유입 경로, 트래픽, **merge 기준 대비 현재 값과 남은 기한** |
| **inbox** | 문의 목록. 상태: 새 문의 · 답장함 · 보관 |

- **가지 등록**: 번호, 이름, 한 줄, 상태, 날짜, 서비스 주소, 분석 연결, merge 기준(지표·목표·기한). 등록한 내용이 공개 페이지 카드가 된다. 한 번 입력하고 두 곳에 쓴다.
- **상태 버튼**: `ship` · `merge` · `close`. 누르면 날짜가 기록된다. 번호는 지우지 않는다.
- merge 기준은 [`branches/README.md`](../branches/README.md) 템플릿의 "검증 기준"과 같은 것이다. 관리자 화면은 그 숫자를 매일 보여주는 곳이다. **Merge what works가 감이 아니라 화면이 된다.**

## 인사이트 — 모을 데이터

**원칙**
- 판단에 쓰는 숫자만 모은다. 모든 숫자는 "이걸 보면 무엇을 정하는가"에 답해야 한다.
- 사람이 아니라 행동을 모은다. 이름·연락처·정밀 위치는 분석 도구에 넣지 않는다.
- **입력한 값은 절대 싣지 않는다.** 핸드머니는 자산관리 앱이다. 금액·계좌·메모는 이벤트에 넣지 않는다. "기록 1건 작성"까지만.
- 모든 가지가 같은 이벤트 이름을 쓴다: `signup` · `core_action` · `purchase` · `error`. 그래야 가지끼리 비교된다.

### A. 포트폴리오 페이지 — 인스타가 사람을 데려오는가

| 데이터 | 보는 것 | 정하는 것 | 단계 |
|---|---|---|---|
| 방문자 (일·주·월) | 링크가 일하는가 | 게시 주기 | v0 |
| 유입 경로 | 바이오 · 스토리 · 검색 · 직접 | 힘을 줄 채널 | v0 |
| 재방문 비율 | 다시 오는 사람 | 업데이트가 사람을 부르는가 | v0 |
| 스크롤 깊이 | 만든 것·문의까지 내려오는가 | 블록 순서 | v0 |
| 카드 클릭 | 가지별 관심 | 홍보할 가지 | v0 |
| 바로가기 클릭 | 포트폴리오 → 서비스로 넘어간 수 | 제품 홍보 목적이 작동하는가 | v0 |
| 문의 전환 | 방문 대비 문의 제출 | 문의 블록 문구 | v1 |

- 링크 꼬리표: 바이오 `?utm_source=instagram&utm_medium=bio`, 스토리 `?utm_source=instagram&utm_medium=story&utm_campaign=post-NNN`.

### B. 가지(서비스) — 반응이 오는가

모든 가지 공통. 가지 저장소에서 출시 **전에** 심는다.

| 묶음 | 데이터 | 정하는 것 |
|---|---|---|
| 들어오기 | 신규 사용자, 가입, 유입 경로 | 홍보가 먹히는가 |
| 쓰기 | DAU · WAU · MAU, 핵심 행동 수 | 실제로 쓰이는가 |
| **붙기** | **리텐션 D1 · D7 · D30**, DAU/MAU (고착도) | **merge 판단의 중심** |
| 품질 | 오류·크래시 비율, 응답 속도 | 새 기능보다 고칠 것이 먼저인가 |
| 트래픽 | 페이지뷰, 요청 수 | 무료 한도와 비용 |
| 돈 *(유료화 후)* | 매출, 유료 전환율 | 사업이 되는가 |

> 사용자 수는 홍보로 올릴 수 있다. 리텐션은 못 올린다. 1인이 키울 가치가 있는지는 **돌아오는 사람**이 말해준다. merge 기준에는 리텐션을 하나 이상 넣는다.

### C. 문의

| 데이터 | 정하는 것 |
|---|---|
| 주간 문의 수 | 포트폴리오가 기회를 만드는가 |
| 답장까지 걸린 시간 | 내가 지키는 숫자. 목표를 정해 둔다 |
| 분류 (광고 · 제휴 · 협업 · 기타) + 결과 (성사 · 보류 · 거절) | 어떤 문의가 실제로 되는가. 분류는 관리자 내부용 — 공개 페이지에는 나열하지 않는다 |

- 메일로 직접 온 문의는 자동으로 잡히지 않는다. 필요하면 inbox에 직접 추가.

### D. 브랜처 전체 — 계속 뻗고 있는가

추적 코드 없이 가지 등록 정보에서 계산한다.

| 데이터 | 보는 것 |
|---|---|
| 상태별 가지 수 | open · shipped · merged · closed |
| open → shipped 기간 | Ship fast의 증거 |
| 마지막 출시 뒤 지난 날 | 오픈 주기 (Q4) |
| merge 비율 | 내놓은 것 중 키운 것 |

### 단계별

| 단계 | 모으는 것 | 보는 곳 |
|---|---|---|
| v0 | A (문의 전환 빼고) | 분석 도구 화면 |
| v1 | + A 문의 전환, C | inbox |
| v2 | + B (돈 빼고), D | `main` · `branch NN` |
| 유료화 후 | + B 돈 | `branch NN` |

## 숫자의 정의

브랜처는 숫자로 말한다. 가지마다 정의가 다르면 숫자끼리 비교할 수 없다.

| 지표 | 정의 |
|---|---|
| 방문자 | 기간 안의 고유 방문자. 포트폴리오 페이지 전용 |
| 사용자 | **핵심 행동**을 1번 이상 한 고유 사용자. 가지를 열 때 핵심 행동 하나를 정한다 (예: 핸드머니 = 기록 1건) |
| DAU / WAU / MAU | 그날 / 최근 7일 / 최근 30일의 사용자. 달력 주·월이 아니다 |
| 유입 | 첫 방문 경로. 인스타 링크에는 `?utm_source=instagram&utm_medium=bio`를 붙인다 |

- 화면의 모든 숫자는 고정폭 숫자(`tnum`).
- 숫자는 관리자 모드에만 둔다. 공개 페이지에는 보이지 않는다 (2026.11.25).

## 디자인

브랜드북을 그대로 따른다. 웹에서 정한 것만 적는다.

- 배경 블랙 기본. 그린은 결과물(출시된 가지의 스퀘어)과 주요 버튼 하나에만.
- 카드·버튼·입력칸: 대각 라운드 — `border-radius: R 0 R 0` (왼쪽 위·오른쪽 아래만). 그림자·그라데이션 없음.
- 서체: Pretendard 700 / 600 / 400. 저장소의 `brand/fonts/`를 쓴다.
- 파비콘: `brand/logo/brancher-favicon.svg`. 설치 아이콘: 블랙 배경 심볼, 512 캔버스째로.
- 관리자 차트: 선 하나는 그린, 나머지는 회색. 색으로 가지를 구분하지 않는다 — 가지 이름으로 구분한다.

## 만드는 방법 — 시안은 아티팩트, 운영은 brancher.kr

아티팩트로 화면을 먼저 만들고 고친다. 화면이 정해지면 그 HTML을 가져와 `brancher.kr`에 올린다.

| | 아티팩트 (시안) | `brancher.kr` (운영) |
|---|---|---|
| 역할 | 화면을 빨리 보고 고친다 | 방문자가 온다 |
| 주소 | claude.ai 링크 | `brancher.kr` |
| 분석 스크립트 | 정해진 CDN만 허용 → 못 심는다 | 심는다 |
| 문의 저장·메일 알림·로그인 | 서버가 없다 | 된다 |

**아티팩트 링크를 그대로 운영에 쓰지 않는 이유**
- 인스타 링크가 `claude.ai` 주소가 된다. 브랜드 주소가 아니다.
- 분석 스크립트를 못 심는다. 숫자가 첫날부터 쌓이지 않는다.
- 문의 폼·관리자 로그인·분석 API 키를 둘 서버가 없다. HTML 안에 키를 넣으면 누구나 본다.

**HTML 한 장 자체는 문제가 아니다.** v0 공개 페이지는 정적 HTML 한 장이면 충분하다. 옮길 때 할 일:
1. 아티팩트 전용 코드를 걷어낸다.
2. 분석 스크립트, 공유 미리보기(OG 이미지·제목·설명), 파비콘, 설치 아이콘을 넣는다.
3. Pretendard는 `brand/fonts/`에서 직접 불러온다.

v1부터 서버가 필요해지면 프레임워크로 옮긴다. 다시 짜는 건 화면 코드뿐이다. 색·서체·모서리·문구는 그대로 간다.

## 기술 — 구현 단계에서 확정

브랜드 쪽 조건만 적는다.

- 비용: 도메인 외 월 0원으로 시작한다. 무료 한도를 넘으면 그게 merge 신호다.
- 주소: `brancher.kr`. 관리자는 같은 주소의 `/admin`.
- 개인 이름이 화면, 메타 정보, 저작권 표기 어디에도 나오지 않게 한다. 저작권은 `© brancher`.
- 제안 구성 *(가격·한도는 도입 시 확인)*:
  - 화면·배포: Next.js + Vercel
  - 데이터·로그인·문의 저장: Supabase
  - 분석: PostHog — 웹과 앱을 같은 도구로 재고, API로 관리자 화면에 숫자를 가져온다
  - 문의 메일 알림: Resend
